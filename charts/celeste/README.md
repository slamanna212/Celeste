# celeste Helm chart

Deploys the whole Celeste stack into one namespace: bot (+ web panel), Lavalink, the yt-dlp resolver (default YouTube
backend) or yt-cipher (plugin backend), a CloudNativePG Postgres cluster, ExternalSecrets, NetworkPolicies and optional
ServiceMonitors. No third-party subcharts, no Ingress/LoadBalancer, no cloudflared (bring your own tunnel).

```
helm install celeste oci://ghcr.io/slamanna212/charts/celeste --version 0.1.0 -n celeste --create-namespace -f values.yaml
```

Resource names derive from the release name (`<r>-bot`, `<r>-lavalink`, `<r>-resolver`, `<r>-yt-cipher`, `<r>-postgres`).
See [VERIFICATION.md](VERIFICATION.md) for the upstream facts behind the templates.

## Prerequisites (not installed by the chart)

| What | Notes |
|---|---|
| CloudNativePG operator | Chart repo `https://cloudnative-pg.github.io/charts`, chart `cloudnative-pg`, namespace `cnpg-system` (the NetworkPolicy assumes this; see `networkPolicy.cnpgOperatorNamespace`). Install it first or the `Cluster` will not be reconciled. |
| External Secrets Operator + `ClusterSecretStore` | Default store `azure-keyvault`, API `external-secrets.io/v1`. |
| k8up | Optional but expected: you own the `Schedule`/`Repository` for the namespace. The chart only adds annotations. |
| Prometheus Operator CRDs | Only when `metrics.serviceMonitor.enabled` or `postgres.monitoring.podMonitor.enabled`. |
| Your own Cloudflare tunnel | Point a hostname at `http://<r>-bot.<ns>.svc:8080`. Never route 9090. |
| Azure Key Vault secrets | See the table below (names are values under `externalSecrets.akv`). |

No runtime config (owners, guilds, panel URL, defaults, radio sources) lives here; it is set with `/admin` and stored in Postgres.

## Backend switching

Set `youtube.backend` and sync. Only one backend is active at a time.

- `ytdlp` (default): resolver Deployment (2 replicas + bgutil sidecar) + Service; Lavalink config enables LavaSrc `ytdlp` pointing at the baked shim; the shim calls `RESOLVER_URL` (`http://<r>-resolver:8080`). No Maven egress needed.
- `plugin`: yt-cipher Deployment + Service; Lavalink config declares `youtube-plugin` as a `lavalink.plugins` dependency (downloaded into the plugins emptyDir at start, needs egress to `maven.lavalink.dev`), disables LavaSrc `ytdlp`, and points `remoteCipher` at `http://<r>-yt-cipher:8001`.

The Lavalink ConfigMap checksum is a pod annotation, so a backend or config change restarts Lavalink; the bot gets `YOUTUBE_BACKEND` (and `RESOLVER_URL` only for ytdlp) and rolls too. Switching drops active playback once; the bot resumes players from Postgres.

## NetworkPolicies

Ingress only (egress is allow-all): Lavalink 2333 <- bot; resolver 8080 <- Lavalink (bgutil's 4416 is not listed and is bound to loopback); yt-cipher <- Lavalink; Postgres 5432 <- bot and same-cluster pods, 5432+8000 <- CNPG operator (`cnpg-system`, `app.kubernetes.io/name=cloudnative-pg`); bot 8080 <- tunnel namespace, 9090 <- monitoring namespace. Kubelet probes: Cilium allows host-to-pod probe traffic by default; on a CNI that does not, add a rule for the node CIDR.

## Backup and restore (k8up)

With `postgres.k8up.enabled` the Cluster gets `inheritedMetadata.annotations`, applied by CNPG to the instance pods and their PVCs:

- pods: `k8up.io/backupcommand: sh -c 'pg_dump --clean --if-exists -Fc celeste'`, `k8up.io/file-extension: .dump`, `k8up.io/backupcommand-container: postgres` (runs as `postgres` over the local socket with peer auth);
- PVC: `k8up.io/backup: "false"` so the raw PGDATA volume is skipped (k8up reads this only on PVCs; it is ignored on pods).

Your k8up `Schedule` in the namespace then stores `<pod>.dump` per snapshot. Verify once: `kubectl -n celeste get pvc -o yaml | grep k8up.io/backup`.

Restore:

1. Deploy the chart so CNPG creates a fresh empty cluster with the `celeste` database. Scale the bot to 0: `kubectl -n celeste scale deploy/celeste-bot --replicas=0`.
2. Fetch the dump from the k8up repository (k8up `Restore` to a PVC/S3, or `restic restore` against the repo; the dump is a file inside the snapshot named after the pod).
3. Load it: `kubectl -n celeste cp celeste-postgres-1.dump celeste-postgres-1:/tmp/db.dump -c postgres` then
   `kubectl -n celeste exec celeste-postgres-1 -c postgres -- pg_restore --clean --if-exists --no-owner --role=celeste -d celeste /tmp/db.dump`
   (the dump was made with `--clean --if-exists`, so it also restores onto a populated database).
4. Scale the bot back to 1.

## Development

```
helm lint charts/celeste -f charts/celeste/values-example.yaml --set youtube.backend=plugin
helm template celeste charts/celeste -n celeste -f charts/celeste/values-example.yaml | kubeconform -strict -ignore-missing-schemas \
  -schema-location default -schema-location 'https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json'
```

Chart `version`/`appVersion` are rewritten from the git tag in CI (`release.yml`); the committed values are `0.1.0`.
