| lavalink-client queue store interface shape                            | `QueueStoreManager { get, set, delete, stringify, parse }`: a KV store of one whole `StoredQueue { current, previous, tracks }` per guild. So the spec's JSONB fallback is used: table `queue_store (guild_id pk, data jsonb)`. The normalized `queue_items` table is not created; item identity (`itemId`, `addedAt`, requester) lives in track `userData`/`requester` inside the JSON. `player_state` is still separate.                                                                                                                                | `index.d.ts` lines ~138-154 (`StoredQueue`, `QueueStoreManager`)                                                                                                                                                                               |
| Session resuming                                                       | Node option `sessionId` sends the `Session-Id` header; `ready` op carries `resumed`; the lib emits `resumed` with the Lavalink player list. `updateSession(true, timeout)` passes `timeout` through unchanged and Lavalink expects **seconds**, so the bot sends `120`. The `ready` op is read from the node `raw` event to persist the session id.                                                                                                                                                                                                       | `index.mjs` (`connect`, `message`, `updateSession`); https://lavalink.dev/api/rest.html#update-session ("timeout in seconds, default 60")                                                                                                      |
| Team role model                                                        | Team member `role` values: `admin`, `developer`, `read_only`; `membership_state` 1 INVITED / 2 ACCEPTED; the team owner is not represented in `role` and is identified by `owner_user_id`. Bot treats `owner_user_id` plus ACCEPTED admin/developer members as owners. discord.js 14.27 exposes `Team#ownerId`, `TeamMember#role`, `TeamMemberRole`.                                                                                                                                                                                                      | https://docs.discord.com/developers/topics/teams ; discord.js typings                                                                                                                                                                          |

| Do DMs with the bot require a shared guild?                            | **Not conclusively documented.** Discord's docs say BOT_DM = "interaction usable within DMs with the app's bot user" but do not state the mutual-guild rule. | AzuraCast real-time now playing                                        | **Yes, SSE via Centrifugo**: `GET <base>/api/live/nowplaying/sse?cf_connect=<urlencoded JSON {"subs":{"station:<shortcode>":{"recover":true}}}>`.
